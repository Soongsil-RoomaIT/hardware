# DHT11 + DFR0030: 처음 연결하는 순서

이 문서는 기존 가이드의 실행 코드를 실제 `examples/read_dht11_window_touch.py`로 옮긴 최신판입니다.
**컴퓨터에서는 파일을 편집하고, 센서 코드는 라즈베리파이에서 실행합니다.**
전원은 배선을 모두 확인한 뒤 마지막에 연결하세요.

## 1. 준비물과 센서 구분

라즈베리파이(40핀), DHT11 3핀 모듈, DFR0030 터치센서, a~j/1~30 브레드보드,
점퍼선, DFR0030용 PH2.0-3 케이블이 필요합니다.
사진의 DHT11처럼 3핀 모듈에 저항이 이미 있다면 일반적으로 추가 풀업은 필요하지 않습니다.
파란 센서만 있는 4핀 부품은 이 표의 대상이 아닙니다.

DFR0030의 흰 커넥터는 PH2.0-3 케이블이 필요합니다. **선 색이나 커넥터 좌우를 추측하지 말고
기판의 VCC/+ · GND/- · S/OUT 표시나 해당 제품 핀도를 확인하세요.**
사진만으로 세 핀의 좌우 순서를 확정할 수 없으므로 이 문서는 기능명 기준으로 연결합니다.
케이블 끝이 암 커넥터면 브레드보드에 꽂을 수 있도록 수 점퍼/어댑터가 필요합니다.

## 2. 브레드보드 구멍 읽기

`a1`은 a열의 1번 줄입니다. `a1~e1`은 내부에서 서로 연결됩니다.
`a2~e2`는 별도 연결이며, 중앙 홈 너머 `f1~j1`도 별도입니다.
이 실습은 옆의 길쭉한 빨강/파랑 전원 레일을 쓰지 않습니다.
센서를 브레드보드 같은 줄에 직접 꽂으면 전원과 신호가 단락될 수 있으므로 **각 핀을 점퍼선으로 연결**합니다.

## 3. Pi에서 브레드보드로 연결

아래 **물리 핀 번호**는 40핀 헤더의 실제 위치 번호입니다.
GPIO4와 물리 4번은 다릅니다. 물리 4번은 5V이므로 혼동하면 안 됩니다.
Pi 기판의 1번 표시/공식 모델 핀도를 확인하세요. 보드가 돌아가 있으면 위아래 기준도 바뀝니다.

| 순서 | 라즈베리파이 출발점 | 브레드보드 도착 구멍 | 용도 |
|---|---|---|---|
| 1 | 물리 1번: 3.3V | a1 | 센서 전원 |
| 2 | 물리 6번: GND | a2 | 공통 접지 |
| 3 | 물리 7번: GPIO4 | a10 | DHT 데이터 |
| 4 | 물리 18번: GPIO24 | a15 | 터치 출력 |

Pi 쪽에는 암, 브레드보드 쪽에는 수 단자가 있는 점퍼선을 씁니다.

## 4. 센서에서 브레드보드로 연결

| 순서 | 센서 핀의 실제 표시 | 꽂을 구멍 | 같은 줄에서 만나는 Pi 신호 |
|---|---|---|---|
| 5 | DHT11 VCC / + | b1 | 3.3V |
| 6 | DHT11 GND / - | b2 | GND |
| 7 | DHT11 DAT / OUT / S | b10 | GPIO4 |
| 8 | DFR0030 케이블 VCC | c1 | 3.3V |
| 9 | DFR0030 케이블 GND | c2 | GND |
| 10 | DFR0030 케이블 Signal | c15 | GPIO24 |

확인: 1번 줄에는 전원만, 2번 줄에는 GND만, 10번 줄에는 DHT 신호만,
15번 줄에는 터치 신호만 있어야 합니다. HC-SR04는 이번 실습에서 연결하지 않습니다.

## 5. 설치와 실행

README 4~5번 설치를 **라즈베리파이 터미널**에서 완료한 뒤:

```bash
cd hardware
source .venv/bin/activate
python examples/read_dht11_window_touch.py
```

예시 출력(실제 측정 기록이 아닌 설명용):

```json
{"touch": true, "window": "unknown", "measured_at": 1790900000.0, "temperature": 25.0, "humidity": 55.0, "co2": null, "pm25": null, "notice": "기준 미만"}
```

- `touch`: 손으로 터치할 때 바뀌는지 확인할 원시 신호입니다.
- `window=unknown`: 아직 실제 창문 설치를 검증하지 않았다는 뜻입니다.
- `co2=null`, `pm25=null`: 센서가 없어 측정하지 않았다는 뜻입니다. 0ppm이 아닙니다.
- 온도 28°C 이상 또는 습도 70% 이상이면 `고온/다습 감지` 문구가 나옵니다.
  이 기준은 학습용이며 자동으로 모터를 움직이지 않습니다.
- 체크섬 오류 등 `sensor_error`가 나면 2초 뒤 다시 시도합니다. 계속 실패하면 배선을 확인합니다.

## 6. 창문 상태로 사용하려면

정전식 터치는 **손/물체에 의한 정전용량 변화**를 읽습니다. 일반 압력 스위치가 아닙니다.
금속 테이프가 닿는다고 항상 닫힘 출력이 유지되는 것은 아닙니다.

1. 손으로 만져 `touch`가 true/false로 바뀌는지 확인합니다.
2. 창문에 센서와 대상물을 고정하고, 손을 떼어도 닫힘 신호가 유지되는지 확인합니다.
3. 최소 10분간 닫아 두고 열기/닫기를 20회 반복해 지속 출력과 재현성을 기록합니다.
4. 전원을 껐다 켜도 같은지 확인합니다. 닫힌 채로 전원을 켜는 경우도 시험합니다.
5. 닫힘에서 true가 안정적으로 유지될 때 아래처럼 실행합니다.

```bash
python examples/read_dht11_window_touch.py --verified
```

터치=true가 실제 열림을 의미하는 설치라면 `--touch-means-open`을 함께 사용합니다.
반복 시험이 실패하면 `--verified`를 사용하지 말고 리드 스위치/마이크로스위치 등
위치를 지속적으로 감지하는 센서로 변경하세요. 이 터치 입력으로 모터의 끝점 보호를 대신하지 않습니다.

## 7. 오류 확인

| 증상 | 먼저 확인할 것 |
|---|---|
| Windows에서 GPIO 오류 | 실제 코드는 라즈베리파이에서 실행했는지 |
| `No module named ...` | `.venv` 활성화 및 `pip install -e '.[hardware]'` |
| DHT 오류가 반복 | DAT가 GPIO4/물리7인지, VCC/GND가 맞는지, DHT11/22 모델 선택 |
| Pi5/OS에서 DHT 동작 불안정 | 사용 중인 Blinka/DHT 버전의 보드 지원, 배선 길이. 정상 확인 전 SHT31로 교체 고려 |
| 터치가 안 바뀜 | PH2.0 케이블 핀 기능, GPIO24/물리18, 3.3V 공급 |
| 닫힘인데 unknown | 정상입니다. 설치 검증 후에만 `--verified` |
| CO₂/PM이 null | 현재 부품으로는 측정할 수 없습니다 |
